01 / Ownership

Accounts the client must control.

A handover is complete only when Mi Amor Tales controls the code, hosting, domain, and original media. Never write passwords in this guide or commit them to GitHub.

AssetCurrent referenceHandover actionStatus
Domainmiamortales.comConfirm registrar owner, billing, recovery email, and two-factor authentication.Confirm
HostingVercelInvite the client as owner/admin of the production project. Confirm billing and alerts.Transfer
Source codegithub.com/varpar/MATAdd the client and future maintainer. Protect main.Transfer
Source mediaClient Google DriveKeep original photographs, films, magazine copy, and usage permissions in a client-owned archive.Confirm
Business emailhello@miamortales.comConfirm mailbox ownership, renewal, recovery, and spam protection.Confirm
CloudinaryOptional utilityKeys in .env.example are for migration scripts. Current public images are local.Optional

Recommended access model

  • Mi Amor Tales owns every primary account and keeps two recovery contacts.
  • The developer receives collaborator access, not the client's password.
  • Enable two-factor authentication everywhere and store recovery codes in a client-owned password manager.
  • Remove former collaborators when their work ends.
Keep secrets out of GitHubReal .env files are ignored. API keys, registrar passwords, email passwords, and Vercel tokens belong in account settings or a password manager.
02 / Hosting

Where the website lives.

The public site is hosted on Vercel. The custom domain points to Vercel, and the root domain redirects to the www address.

Primary address
https://www.miamortales.com

Use this in profiles, QR codes, and client communication.

Technical fallback
https://mat-bay.vercel.app

Keep as a deployment URL, not the public brand address.

Verified behaviour

  • https://miamortales.com redirects to https://www.miamortales.com/.
  • www.miamortales.com resolves through cname.vercel-dns.com.
  • The live response identifies Vercel as the server and uses HTTPS with HSTS.

Final transfer checklist

  1. Open Vercel and identify the project serving the custom domain.
  2. Confirm its Git repository is varpar/MAT and production branch is main.
  3. Invite the client's Vercel account as owner/admin.
  4. Confirm both root and www domains are attached.
  5. Move renewal, billing, and failure notifications to client-controlled addresses.
Do not create a duplicate Vercel projectThe local .vercel folder is ignored. A maintainer using the CLI must run npx vercel link and select the existing production project.

04 / Editing

Common content changes.

Homepage hero photograph

  1. Prepare a strong landscape JPEG with the subject safe in the centre crop.
  2. Replace public/home/hero-aks09773.jpg using the same filename.
  3. If the filename changes, update HERO_IMAGE.publicId near the top of HomeClient.tsx.
  4. Check desktop and phone crops.

About copy and statistics

  • The story and "The Art of Noticing" copy are in AboutClient.tsx.
  • The stats array currently shows 2+ Years, 50+ Weddings, 10+ Cities, and 4-5 Awards.
  • Update related homepage and footer wording when a milestone changes.

Team member

  1. Add or replace the portrait in public/images/team.
  2. Add or update its image record in data.ts.
  3. Edit the team array in AboutClient.tsx.
  4. Use optional crop settings only for small source-image corrections.

Homepage featured film

The homepage currently prefers slug riya-sang-mohit inside HomeVideoSection. Change that slug only after the replacement couple has a valid heroVideo.

Menu and footer

Edit NAV_LINKS in Nav.tsx. Edit business details and footer labels in Footer.tsx. Keep route paths unchanged unless the route itself is changed.

06 / Media

Photos and films that stay fast.

Use fewer, stronger frames. Every image must belong to the named couple and ceremony.
Editorial media rule

Photographs

  • Use JPEG or WebP in sRGB. Recommended long edge: 2000-3000 pixels.
  • Aim for roughly 300 KB-1.5 MB after optimization while preserving full-screen quality.
  • Hero and poster images should be landscape; team and bridal portraits should be vertical.
  • Use lowercase, descriptive, hyphenated filenames without spaces.
  • Keep original full-resolution files in the client Drive. GitHub holds delivery copies.

Films

  • Use MP4 with H.264 video and AAC audio, normally 1920 x 1080 landscape.
  • Enable fast start and aim below 50 MB. GitHub blocks normal files at 100 MB.
  • Supply a poster JPEG for full films.
  • Set withSound: false for silent montages so the interface says "Photo film" and hides sound controls.

Folder pattern

public/images/couple-slug/
  hero.jpg, bride.jpg, groom.jpg
  storyImage1.jpg, storyImage2.jpg
  haldi.jpg, mehendi.jpg, sangeet.jpg
  pheras.jpg, vidaai.jpg, intimateBW.jpg
  closing.jpg, extra1.jpg ...

public/video/featured/couple-slug/
  highlight.mp4
  poster.jpg

Next.js creates AVIF and WebP variants in production, but source files still need sensible dimensions and compression.

07 / Enquiries

Contact details and WhatsApp.

The enquiry form runs in the browser. It builds a readable message from the fields and opens WhatsApp to the studio number.

WhatsApp destination
+91 99284 12112

Stored as WHATSAPP_NUMBER = "919928412112".

Displayed email
hello@miamortales.com

Shown on Contact and in the footer. It is not the form destination.

What submit does

  1. Checks the required name and email fields.
  2. Builds a message with names, email, phone, date, venue, package, and notes.
  3. Opens WhatsApp or WhatsApp Web with the message ready to review.
  4. Sends only when the visitor presses Send inside WhatsApp.
No lead database or automatic emailThe site does not save submissions, send notification emails, or maintain an enquiry dashboard. Add a verified backend and privacy disclosure before collecting data.

Change the WhatsApp number

  1. Edit WHATSAPP_NUMBER in ContactClient.tsx, digits only with country code.
  2. Update the formatted number lower in that file.
  3. Update Footer.tsx.
  4. Test on phone and desktop.

FAQs and social links

Edit FAQS near the top of ContactClient.tsx. Footer social names currently have no external URLs; adding real links requires editing Footer.tsx.

08 / Local setup

Run the website on a computer.

Requirements

  • Git
  • Node.js 20.9.0 or newer
  • npm
  • GitHub repository access

First setup

git clone https://github.com/varpar/MAT.git
cd MAT
npm ci
npm run dev

Open http://localhost:3000.

Before editing

git checkout main
git pull origin main
npm ci

Before publishing

npm run lint
npm run build
Environment variablesNormal viewing needs no Cloudinary credentials because current images are under public. Keys in .env.example are for optional migration scripts. Never commit a real .env.
09 / Publishing

From edit to live website.

DraftMake one focused change on a branch.
ReviewCheck copy, identity, crops, and links.
TestRun lint and production build.
ApproveMerge the approved change to main.
VerifyWait for Vercel, then test live.

Recommended Git workflow

git checkout -b content/update-name
# make and test the change
git add -A
git commit -m "Update featured wedding gallery"
git push -u origin content/update-name

Open a pull request, review the preview deployment, and merge into main. Direct pushes should be limited to trusted maintainers and small approved changes.

Live verification

  • Vercel marks production Ready.
  • The custom domain shows the new revision.
  • All main pages load.
  • The changed page works on phone and desktop.
  • Images, films, navigation, and WhatsApp work.

Rollback

Fast: promote the last known-good deployment in Vercel. Permanent:

git log --oneline
git revert BAD_COMMIT_SHA
git push origin main
Preserve historyDo not force-push or use git reset --hard as a production release strategy. A revert is reviewable and recoverable.
10 / QA

Check before every release.

Content and identity

  • Names and spellings are correct.
  • Every photo belongs to the named couple.
  • Ceremony labels match the visible event.
  • No image repeats unintentionally.
  • Venue, date, stats, email, and phone are current.
  • Stories have client approval.

Visual and functional

  • No overlap or clipped text on phone, tablet, or desktop.
  • Hero subjects crop correctly.
  • Spacing remains intentional.
  • Films and posters are correct.
  • Navigation, filters, lightbox, and form work.
  • Keyboard focus and reduced motion remain usable.

11 / Care

Maintenance and troubleshooting.

Monthly

  • Open all main pages and prepare a test WhatsApp enquiry without sending.
  • Check domain, HTTPS, failed deployments, and bandwidth.
  • Confirm approved work exists in GitHub and source media exists in the client archive.

Quarterly

  • Review dependency updates on a separate branch.
  • Run mobile performance and accessibility checks.
  • Audit team, statistics, details, FAQs, social links, and availability language.
  • Confirm GitHub recovery and backups.

Common problems

ProblemLikely causeFirst action
Old content is liveBuild pending, wrong branch, or cacheCheck Vercel production commit, then hard-refresh.
Image is missingWrong filename, case, or record pathConfirm exact file and matching publicId.
Video does not playEncoding, size, or pathCheck H.264/AAC MP4, file path, poster, and browser console.
Wrong event photoStory slot or ritual extrasFix the couple story in data.ts or hide the ritual.
Wrong WhatsApp numberValues are out of syncUpdate Contact and Footer, then test both devices.
Build failsSyntax, type, import, or missing assetFix the first build error locally before publishing.
Domain failsDNS, renewal, Vercel domain, or billingCheck registrar, Vercel Domains, records, and project owner.

Known improvements

  • Add real URLs to footer social labels.
  • Add a lead backend only if enquiry tracking is required.
  • Set explicit production metadataBase for absolute social previews.
  • Review unused story data before removing it.
  • Protect main with required checks and review.

Update process

  2. Open it in Chrome and review wide and narrow layouts.
  3. Run node handover/export-handover.mjs from the project root.
  4. Inspect every PDF page for clipping, overlap, missing images, or blanks.
  5. Update the cover date and version for every major handover revision.
